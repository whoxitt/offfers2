# Система ключей активации для твинков

## Описание

Новая система привязки твинков через ключи активации. Заменяет старую систему с запросами и подтверждениями.

---

## Как работает

### 1. **Покупка / Выдача доступа**

Когда человек покупает доступ или админ выдаёт доступ через админку:
- Автоматически генерируется **уникальный ключ активации** формата `KEY-XXXX-XXXX`
- Ключ сохраняется в БД в таблице `access_grants`
- Ключ можно посмотреть в кнопке **"Подписка"**

### 2. **Активация твинка**

На твинке:
1. Нажать кнопку **"🔑 Активировать ключ"**
2. Ввести ключ от основного аккаунта: `KEY-XXXX-XXXX`
3. ✅ Твинк привязан! Доступ действует до тех пор, пока действует подписка основного аккаунта

### 3. **Смена твинка**

- На новом твинке вводим тот же ключ
- Старый твинк **автоматически отключается**
- Новый твинк получает доступ
- Старому твинку приходит уведомление об отвязке

### 4. **Просмотр ключа**

Основной аккаунт нажимает **"Подписка"** и видит:
```
📊 Подписка

Осталось: 47 ч. 30 мин.

🔑 Ключ для активации твинка:
KEY-A1B2-C3D4

👤 Привязанный твинк: @username
```

---

## Преимущества

✅ **Просто** - не нужно запрашивать username и ждать подтверждения  
✅ **Безопасно** - только владелец ключа может привязать твинк  
✅ **Гибко** - можно менять твинки без участия основного аккаунта  
✅ **Прозрачно** - ключ всегда виден в подписке  
✅ **Работает с админкой** - даже если админ выдаёт доступ вручную, ключ генерируется автоматически

## Технические детали

### База данных

#### Новая таблица `access_grants`:

```sql
CREATE TABLE access_grants (
    user_id BIGINT PRIMARY KEY,
    activation_key TEXT UNIQUE,              -- Ключ для активации твинка
    linked_to_user_id BIGINT,                -- ID основного аккаунта (если это твинк)
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_access_grants_activation_key ON access_grants(activation_key);
CREATE INDEX idx_access_grants_linked_to ON access_grants(linked_to_user_id);
```

#### Поля:
- `user_id` - ID пользователя (основного или твинка)
- `activation_key` - уникальный ключ (только у основных аккаунтов)
- `linked_to_user_id` - NULL для основных, ID основного для твинков
- `created_at`, `updated_at` - служебные поля

#### Миграция:

Файл: `migrations/003_activation_keys.sql`

Запускается автоматически при старте бота через `init_schema()`.

### Функции database.py

#### Генерация ключа:
```python
db.generate_activation_key()  
# → "KEY-A1B2-C3D4"
```

#### Создание ключа для пользователя:
```python
key = db.create_activation_key_for_user(user_id)
# → создаёт или возвращает существующий ключ
```

#### Получение ключа:
```python
key = db.get_activation_key(user_id)
# → "KEY-A1B2-C3D4" или None
```

#### Проверка ключа:
```python
info = db.validate_activation_key("KEY-A1B2-C3D4")
# → {'owner_user_id': 123, 'expires_at': datetime, 'linked_twink_id': 456 или None}
# → None если ключ невалидный
```

#### Активация твинка:
```python
result = db.activate_twink_with_key(twink_user_id, "KEY-A1B2-C3D4")
# → {'success': True, 'owner_user_id': 123, 'old_twink_id': 456 или None, ...}
# → {'success': False, 'error': 'invalid_key', 'message': '...'}
```

#### Отвязка твинка:
```python
success = db.deactivate_twink(twink_user_id)
# → True/False
```

#### Получить ID привязанного твинка:
```python
twink_id = db.get_linked_twink(owner_user_id)
# → ID твинка или None
```

#### Получить информацию о твинке:
```python
info = db.get_twink_info(twink_user_id)
# → {'owner_user_id': 123, 'activation_key': 'KEY-...', 'expires_at': datetime, ...}
# → None если это не твинк
```

### Автоматическая генерация ключей

Ключ генерируется автоматически в следующих функциях:

1. **`grant_paid_access(user_id, hours, source)`** - админ выдаёт доступ
2. **`confirm_payment_and_grant_access(payment_id, user_id, duration_hours)`** - оплата через TON Wallet
3. **`confirm_payment_access_and_reward_referrer(...)`** - оплата + реферальная награда

Во всех случаях после выдачи доступа выполняется:
```python
key = self.generate_activation_key()
cur.execute("""
    INSERT INTO access_grants(user_id, activation_key, linked_to_user_id)
    VALUES(%s, %s, NULL)
    ON CONFLICT(user_id) DO UPDATE SET activation_key=EXCLUDED.activation_key
""", (user_id, key))
```

## Кнопки и команды

### Главное меню:

**Для основного аккаунта:**
- **"Подписка"** - показывает срок, ключ активации, статус твинка
- **"🔑 Активировать ключ"** - начать процесс активации (если нет доступа)
- **"🔄 Отвязать твинк"** - отвязать себя от основного аккаунта (если это твинк)

**Для твинка:**
- **"Подписка"** - показывает информацию об основном аккаунте
- **"🔑 Активировать ключ"** - ввести ключ для привязки
- **"🔄 Отвязать твинк"** - отвязаться от основного

### Команды:

- `/cancel` - отменить ввод ключа

## Старая система (закомментирована)

Старые обработчики оставлены в коде как комментарии:
- `@dp.callback_query(F.data == "reset_my_accounts")`

- `@dp.callback_query(F.data.startswith("access_link_yes:"))`
- `@dp.callback_query(F.data.startswith("access_link_no:"))`

## Безопасность

✅ **Ключ уникальный** - нельзя создать дубликат  
✅ **Проверка срока** - твинк не активируется, если доступ истёк  
✅ **Защита от самоактивации** - нельзя использовать свой ключ  
✅ **Автоматическая очистка** - при отвязке все связи удаляются  

---

## Обратная совместимость

Старая система (`offer_access_links`) продолжает работать:
- Старые твинки через `offer_access_links` продолжают иметь доступ
- Функция `has_access()` проверяет обе системы
- Новые привязки создаются через `access_grants`

## Логирование

- Активация твинка
- Отвязка твинка
- Уведомления админу
